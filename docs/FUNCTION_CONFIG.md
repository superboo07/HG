# Standalone Function Configuration

Ghidra is an optional analysis tool, not part of recompilation. The boundary is
a plain CSV with the columns `Name,Start,End,Size`. PS2Recomp reads this file at
recompilation time; it does not open or query a Ghidra project.

Human-reviewed additions belong in `config/functions.manual.toml`. Each entry
requires a unique name, half-open aligned address range, action mode, confidence,
evidence, and reason. Supported modes are:

- `recompile`: compile the guest instructions normally.
- `runtime_bind`: add the function and bind its start to a named runtime handler.
- `skip_for_triage`: emit a skipped wrapper temporarily; release generation
  rejects this mode.

Set `override_analysis = true` only for a reviewed boundary correction whose
start exactly matches an analyzer entry. The merger removes that one analyzer
record before validation and substitutes the manual record. It rejects an
override with no matching start, so a stale correction cannot silently turn
into an unrelated new function.

Reviewed monotonic function-pointer tables can be expressed without duplicating
hundreds of entries:

```toml
[[function_tables]]
name_prefix = "static_init"
table_start = 0x00469460
table_end = 0x0046969C
code_end = 0x00469460
override_analysis = true
confidence = "high"
evidence = "reviewed startup call loop and pointer table"
reason = "data-referenced functions omitted by analysis"
```

The table bounds are half-open and must refer to file-backed ELF data. Every
word must be a four-byte-aligned, strictly increasing function address. The
merger derives each function's exclusive end from the next pointer and uses
`code_end` for the final entry. It emits ordinary bounded manual functions, so
PS2Recomp still receives only the verified ELF and standalone CSV/TOML. A table
with `override_analysis = true` replaces analyzer records only where their
starts coincide; unlike a single-function override, most table entries may be
genuine analyzer omissions.

Large reviewed waves use exact record sets. Boundary corrections must preserve
the analyzer endpoint they were reviewed against:

```toml
[[function_sets]]
name_prefix = "reviewed_epilogue"
override_analysis = true
confidence = "high"
evidence = "verified ELF CFG and return"
reason = "analyzer omitted the epilogue"
ranges = [
  { start = 0x00100000, analysis_end = 0x00100020, end = 0x00100030 },
]
```

Wholly omitted functions use `[[missing_function_sets]]` with exact
`{ start, end }` records. The merger rejects stale analysis ends, missing
override starts, duplicate starts/names, overlaps, unaligned or out-of-range
bounds, and ELF build mismatch for both forms.

Generate effective inputs with Python 3.11 or newer:

```powershell
python tools/merge_function_config.py `
  --elf "Haunting Ground (USA)/SLUS_210.75" `
  --analysis-map config/functions.analysis.csv `
  --analysis-source standalone_analysis `
  --base-config config/recomp.base.toml
```

The approved standalone inputs in `config/` are sufficient for a clean build;
neither Ghidra nor its project/database is consulted. The default outputs are
`build/generated/functions.effective.csv`,
`build/generated/recomp.effective.toml`, and
`build/generated/functions.provenance.csv`. All three are disposable and
ignored. The provenance report records the origin, mode, confidence, evidence,
and reason for every emitted boundary. The
tool verifies the ELF hash, MIPS ELF format, executable address bounds,
alignment, names, starts, overlaps, modes, and required evidence before writing.
The optional base analyzer TOML supplies runtime stubs, MMIO observations, jump
tables, and instruction patches; the merger preserves those fields.
Reviewed false-positive runtime bindings can be removed by exact specification
with `recompiler.exclude_base_stubs` in `config/game.toml`. This is intended for
same-named guest library helpers that the analyzer incorrectly bound to a host
handler; each excluded entry is then recompiled from the standalone function
map normally.
Reviewed false-positive instruction rewrites can likewise be removed by exact,
aligned address with `recompiler.exclude_base_patches`. All other analyzer
patches remain preserved; the exclusion only prevents the matching inherited
patch from being emitted into the effective config.

Manual functions require a complete standalone analysis map. A partial CSV is
unsafe because upstream PS2Recomp treats a successfully loaded map as
authoritative and can discard heuristic auto-generated entries not present in
it. Until a complete Ghidra/exported map exists, use the native analyzer TOML
directly without manual entries.

The merger prefixes Ghidra-style autogenerated names with address-based
`ghidra_` names. PS2Recomp classifies `FUN_`, `sub_`, `LAB_`, and `DAT_` as
heuristic names and otherwise may choose a longer native-heuristic range over an
exported range at the same start. The provenance-qualified name makes the
standalone map boundary authoritative and also prevents C++ name collisions.

Ghidra function bodies can be discontiguous: their maximum address may be a
distant shared tail even when only a few bytes belong to the body. Because
PS2Recomp expects contiguous `[Start, End)` ranges, the merger clamps an exported
range at the next function start whenever that start lies inside the span. This
removes overlap and prevents data/other functions between body fragments from
being recompiled as part of one giant function.

The field name `ghidra_output` in the generated PS2Recomp TOML is retained only
because that is the upstream configuration key. Its value is an ordinary CSV
and has no live Ghidra dependency.

When staging a generated version into the disposable runtime source, always
pass `--retain-generated-versions 10`. The guarded cleanup recognizes only
exact numeric `recompiled-vN` siblings and must not be replaced with broad
directory deletion.

Audit the effective map with:

```powershell
python tools/report_function_coverage.py `
  --elf "Haunting Ground (USA)/SLUS_210.75" `
  --map build/generated/functions.effective.csv `
  --config build/generated/recomp.effective.toml `
  --json-out build/analysis/function-coverage.json
```

The report measures executable-byte coverage, gaps, overlaps, unusually large
functions, indirect `JR`/`JALR` sites, and direct executable branch targets that
have no owning function. A nonzero exit status indicates overlapping ranges.

Additional ELF-only discovery passes are available:

```powershell
python tools/audit_function_boundaries.py `
  --elf "Haunting Ground (USA)/SLUS_210.75" `
  --analysis-map config/functions.analysis.csv `
  --effective-map build/generated/functions.effective.csv `
  --manual config/functions.manual.toml `
  --all-prologues `
  --json-out build/analysis/function-boundaries.json

python tools/audit_data_function_pointers.py `
  --elf "Haunting Ground (USA)/SLUS_210.75" `
  --map build/generated/functions.effective.csv `
  --json-out build/analysis/data-function-pointers.json

python tools/audit_gap_leaf_functions.py `
  --elf "Haunting Ground (USA)/SLUS_210.75" `
  --map build/generated/functions.effective.csv `
  --json-out build/analysis/gap-leaf-functions.json
```

The first pass checks all analyzed stack-frame functions, including
indirect-only functions, and requires delay-slot-aware reachable termination
before the next analysis or manual start. The second scans pointer-dense
file-backed ELF data for uncovered function-like targets, including bounded
frameless methods with contained local branches. Feed its JSON to
`audit_missing_pointer_functions.py` to resolve a non-overlapping subset.
Residual shared-suffix or jump-table labels are triage findings, not permission
to create overlapping functions.

Use `audit_function_boundaries.py --allow-zero-runs` as a second, stricter-review
pass for stack-frame functions containing intentional NOP-filled polling loops.
The gap audit begins only at an existing map boundary (or the end of a leaf it
just proved) and stops at the first unprovable sequence; it does not sweep every
instruction address looking for coincidental returns.

After writing all four audit JSON files, produce the complete executable-byte
ledger with:

```powershell
python tools/classify_executable_bytes.py `
  --elf "Haunting Ground (USA)/SLUS_210.75" `
  --map build/generated/functions.effective.csv `
  --coverage-audit build/analysis/function-coverage.json `
  --pointer-audit build/analysis/data-function-pointers.json `
  --boundary-audit build/analysis/function-boundaries.json `
  --leaf-audit build/analysis/gap-leaf-functions.json `
  --json-out build/analysis/executable-byte-classification.json
```

The classifier refuses to write a completion ledger unless the direct-target,
pointer-target, boundary, invalid-manual-set, and gap-leaf gates are all clear.
