# OpenGL GS renderer design

Status: live hybrid implementation for a differentially verified gameplay T8
subset. The CPU renderer remains the correctness reference and ordered fallback
for unsupported or overlapping states. Current profiling shows that VU1
geometry production, not GPU raster completion, is the dominant speed blocker.

## Current implementation checkpoint

Gates 1 and 2 are verified on the available Windows/NVIDIA RTX 5070 host. The
runner obtains an OpenGL 4.3 context, passes the compute/SSBO roundtrip, and
matches 65,536 deterministic CT32, Z24/Z32, T8, and CSM1 CLUT address cases.
The CPU backend remains available on Apple, older OpenGL hosts, and as the live
fallback. Evidence is:

- `build/phase3/phase4-v163-opengl43-probe.log`
- `build/phase3/phase4-v163-opengl-address-map-probe.log`
- `build/phase3/ps2x-tests-v163-opengl43-foundation.log`
- `build/phase3/ps2x-tests-v163-opengl-address-map.log`

Gate 3 is now live for the exact captured T8/STQ/MODULATE/CT32/Z24 gameplay
state. The ordered hybrid backend keeps raw GS VRAM in one 4 MiB SSBO, queues
immutable draws from the GS worker, executes OpenGL commands on the Raylib
context-owning display thread, and reads back before CPU fallback, transfer, or
presentation operations. It batches as many as 256 consecutive exact-state
draws, preserves their per-pixel order in the shader, and dispatches only their
conservative union bounding box. `PS2X_DISABLE_OPENGL_GS` disables the live
route for differential diagnosis.

A real captured draw matches all 4 MiB of CPU VRAM exactly, including 1,001
changed bytes. A 64-draw ordered batch derived from the real capture also
matches exactly. The deterministic route produces a coherent gameplay frame;
`PS2GS` passes 87/87 after integration. Evidence is:

- `build/phase3/phase4-v163-opengl-live-t8-replay-probe-r2.log`
- `build/phase3/phase4-v163-opengl-live-batch-probe-r2.log`
- `build/phase3/ps2x-tests-v163-opengl-live-batch.log`
- `build/phase3/phase4-v163-opengl-live-route-capture.log`

The GPU path is not the current throughput limit. Completing 100,002 live
triangles consumed approximately 53.4 ms of cumulative GPU time and 200,023
consumed about 104.7 ms, while the producer needed roughly nine seconds of wall
time to supply the first 100,000. A matched VIF profile attributes 4,964.61 of
5,484.24 ms (90.5%) to scalar VU1 callbacks. The immediate performance work has
therefore moved to exact native/cached execution of hot VU1 microprogram blocks,
starting at `0x288` and `0x60`; further renderer coverage remains necessary for
correctness and later scenes but cannot supply the missing fivefold speedup by
itself.

The first VU1 hot-path series has since reduced the same 35-chain window to
4,640.94 ms of VU work and 5,152.59 ms total without changing GS output or
guest timing; `PS2VU1` remains 41/41. This is a 6.5% VU improvement, not the
required architectural speedup. The current single-pass exact-FMAC work and
next native-block actions are recorded at the top of `docs/PROJECT_STATUS.md`.

Before broad default-authoritative use, batching must adopt the CPU backend's
proven texture/CLUT/frame/depth alias predicate, the display-thread drain must
have a presentation-safe work budget, and cross-thread queue/state ownership
must receive a focused audit. Any uncertainty closes the GPU batch and uses the
ordered CPU fallback.

## Goals

- Preserve GS command order and guest-visible synchronization.
- Keep one canonical 4 MiB PS2 local-memory image with explicit CPU/GPU dirty
  ranges and transfers.
- Reproduce the game's observed storage formats, swizzling, texture/CLUT
  lookup, alpha and destination-alpha tests, blending, framebuffer masks,
  depth behavior, fog, scissor, and display selection.
- Submit enough work per host call to amortize the tens of thousands of tiny
  triangles generated by each gameplay interval.
- Retain a portable CPU fallback and do not require OpenGL 4.3 on hosts that
  cannot provide it.

## Host/thread model

The game/EE thread produces DMA and VIF work. The ordered GS packet worker
parses GIF packets and emits immutable draw/transfer commands. OpenGL commands
must execute on the host display thread that owns the Raylib context. A
thread-safe FIFO therefore transfers complete GPU command batches to the host
thread. Guest-visible barriers (`FINISH`, path synchronization, local-to-host
reads, presentation snapshots, reset, and backend replacement) wait for the
corresponding GPU generation, while ordinary submission remains asynchronous.

The renderer must not issue OpenGL calls from the GS packet worker. This avoids
platform-specific context migration and retains a single portable context.

## Local memory and batching

OpenGL 4.3 hosts use an SSBO representation of the raw 4 MiB GS local memory.
Host-to-local transfers update exact dirty byte ranges. GPU draws read texture
and CLUT data and write framebuffer/depth through the same PS2 address mapping.
GPU-to-CPU readback occurs only for explicit guest reads, CPU fallback states,
debug/oracle snapshots, and portable presentation conversion checkpoints.

Commands may share a compute/raster batch only while every texture/CLUT source
is independent of earlier framebuffer/depth output. Framebuffer feedback,
overlapping formats, local-to-local transfers, and unsupported states close the
batch and establish an explicit memory barrier. Within a batch, per-pixel draw
order remains the original GIF order.

## Incremental implementation gates

1. Request an optional OpenGL 4.3 context on Windows/Linux and validate compute
   shader plus SSBO roundtrip. Keep macOS/older-host CPU fallback.
2. [Windows/NVIDIA complete] Differentially validate CT32, Z24/Z32, T8, and
   CLUT address mapping against the existing CPU memory implementation.
3. [Windows/NVIDIA live subset complete] Implement the measured unblended,
   linearly filtered T8 triangle hot path. Compare complete VRAM and rendered
   frames against the CPU backend.
4. Add the measured CT32 sprite classes, alpha/depth tests, and blend equations
   so ordinary gameplay frames do not repeatedly fall back/read back.
5. Add transfers, masks, fog, remaining observed formats, feedback barriers,
   and display circuits. Validate movie, UI, character, and room scenes.
6. Broaden default-authoritative coverage only after deterministic route timing,
   alias/concurrency audits, and all differential/oracle checks pass.
   Unsupported states remain explicit and measurable instead of silently
   approximated.

## Validation and provenance

- The existing `PS2GS` suite is the minimum regression gate for every change.
- GPU tests compare exact touched VRAM bytes where possible and tolerant final
  images only where host rasterization rules require it.
- PCSX2 2.6.3 remains the behavioral oracle. PCSX2 source may inform hardware
  semantics, but no source is copied without recording revision, path, license,
  and notices in the provenance ledger.
- Performance comparisons use identical deterministic input routes and report
  normalized per-chain timings plus controller-read checkpoints.
